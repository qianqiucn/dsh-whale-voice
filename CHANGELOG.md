- Fix: Plan 13-B 116 revision" — logical verdict vs execution lease, post-invoke exception classification and contradictory cancel evidence (same PR #51, not merged). `settle()` now fixes the delivery verdict only; the single execution slot is released by trusted exit/recovery evidence instead of by any terminal state. `UNKNOWN`, an unconfirmed cancel, a missing/empty/bad invoke result, a thrown transport and an invoke-returned success that reports `restore_ok:false` all keep the slot occupied (`status.occupancy:'HELD'`, `leaseReleased:false`) while the delivery stays terminal and refuses the same id (`UNKNOWN_NO_RESEND`); the static `recover()` descriptor is not evidence. A `CANCELLED` result claiming `CANCELLED_BEFORE_UI` (or no stage) while carrying `RECORDING`/`SENDING`/release evidence becomes `UNKNOWN` and is not confirmed, while a legal `CANCELLED_CONFIRMED` keeps its recording evidence. Adjacent ordinary items: a queued cancellation resolves its own submit promise immediately, and a failed cancel write returns a verdict that arrived during the write instead of a stale `CANCEL_REQUESTED`.
