# Whale Audio Core · 零编程基础用户优先产品标准（长期强制约束）

**制定：2026-10-25 · 用户明确要求“本项目始终给不会代码的编程小白用，保持易用性”。**

> **最高优先级产品原则：让完全不懂编程、不知道 Python/命令行/Git/API 的普通用户也能够安全完成安装、选择模式、生成语音或翻唱、试听/保存，并在显式授权后发送。** 产品的技术架构可以复杂，但复杂性必须封装在 Whale Audio Core、适配器和经审计的可选安装器内，不能转嫁给用户。此项是**全部未来 Plan/PR/UI 验收的设计门禁**，不是对当前已实现功能的宣称。

## 0. 范围和优先级

适用于 Whale Audio Core（鲸音核心）、Whale Voice（语音气泡）、Whale Singing（唱歌）、Whale Relay（鲸递）、WeChatAgent 对接、Provider 管理、首次使用弹窗、配置、组件管理、升级、日志、帮助与发布。原 Plan 01–14 编号、已有已完成状态和生产安全规则全部不变。

**每次制定 DeepSeek 的 Level 2 任务书或接受 PR 时，必须检查本标准。** 如技术选择需要用户在正常首次使用路径中手工安装 Python/FFmpeg/CUDA、复制代码、编辑 JSON、运行 pip/git/npm 命令、配置复杂端口和环境变量，默认视为**用户体验设计缺陷/未完成**；应由未来受审计的图形安装/管理器代劳，或提供有明确说明的免本地安装的可用替代。不要把“开发者安装说明”包装成初学者可用产品。

## 1. 一般用户实际使用路径（用户旅程）

1. **打开 DSH 插件**：能一眼区分“语音气泡 Whale Voice”和“唱歌 Whale Singing”，中文为主、有清晰图标、功能提示和当前支持状态。共享的 Whale Audio Core 不需要用户理解其进程内部结构。
2. **首次进入任一功能**：弹出该功能独立的依赖检查与安装选择，自动**只读**探测已存在的组件、版本、权限和硬件；选模式而非阅读技术手册。另一个功能的依赖不能成为强制门槛。
3. **选择最容易的可用方案**：按用户设备显示推荐模式，如已有本地模型、可用 CPU 方案或明确授权的云端服务；**不强制显卡、不强制下载多个 GB 模型、不默认引导付费 API、不默认安装聊天发送依赖**。RVC 标准翻唱为首发；Seed-VC 仅为后续可选免训练试唱，不能标低显存或现在可用。
4. **确认后才安装**：清楚展示要下载/安装什么、来源、许可证、预估空间与费用/网络/系统权限。操作系统驱动、模型、付费服务、生产写入、服务启停和真实消息交付分别按既有权限门禁确认；**进入页面不会自动下载或执行命令**。进度和取消/失败恢复须真实可观察。
5. **使用功能**：为非技术用户提供直观的“输入文字/选择歌曲或授权本地音频 → 选择音色 → 生成/翻唱 → 试听 → 保存 → 授权发送”向导，合理默认值可直接使用，非必需高级参数折叠。搜索元数据不等于拥有商业歌曲下载/传播许可。
6. **出错时能自己解决**：错误文案使用简体中文和“为什么/现在怎么办/重试或返回”结构；对网络断开、无 GPU、模型不兼容、磁盘不足、依赖未装、版权/授权缺失、服务不可达、重复投递未知结果分别给安全建议。不要求普通用户复制报错栈或修改程序文件。
7. **下一次进入**：记住用户已确认的模式与向导完成状态，使用可信能力重新核验；同一版本同一功能不反复骚扰。可以随时从“管理依赖/更换模式”进入图形管理入口，复用已安装组件，支持卸载、清理和回退的经授权路径。

## 2. 界面与术语规范（默认中文）

- 主操作按钮使用行动词：“开始生成语音”“开始翻唱”“试听”“保存到本地”“发送到已授权聊天”“检查依赖”“安装所选组件”“以后再说”；不直接使用裸的 `submit`、`applyRevision`、`Adapter`、`Gradio`、`UVR` 等术语做一级按钮。
- 技术名可以在“了解详情/高级设置”展示，但界面先解释其作用，如 RVC=“将歌声转换成选择的音色”，人声分离=“从歌曲中分开主唱与伴奏”，Relay=“把完成的音频安全发送出去”。
- **只有真正接入的功能可点击**：未实现禁用并标“尚未支持”；Fake、演示、只读、离线实现、运行中、已安装未验证、可用、生成完成、已保存、已提交发送、已确认送达都必须有明确不同状态。不能展示虚假的安装百分比、运行成功、模型下载量或发送回执。
- 常见场景不需要用户理解 taskId/ProviderId/音频格式；系统在内部处理选择/转换，必要信息可通过“高级详情”查看，供排错者使用。
- 两页共享音色/Provider/Artifact/任务及唯一 DeliveryId；允许“只生成/试听/保存”而不配置真实微信发送；网页窄屏、键盘导航、焦点恢复、对话框 Esc/取消、可访问性文案均需测试。
- 默认不展示危险开关（原生 Hook、自动切换发送后端、取消安全检查、关安全软件、越过版权/同意验证）。技术上不可行的功能应坦白限制并给安全可行替代，不能假称一键可用。

## 3. 免命令行与组件安装要求

- **面向最终用户的正常流程不得要求打开终端**。后续真正 Installer 应以受审核、可验证下载来源、固定版本/Hash、受限目录、可撤销进度、断点/异常恢复、适当权限与卸载回退为准；本轮**没有真实安装授权**。
- 对需要手工安装的第三方、驱动或有许可争议的组件，显示明确“需要手动安装/当前无法自动安装”的诚实说明和可视化指导；**不得用未经审计脚本伪装一键安装**。必要时向普通用户推荐不依赖该组件的替代工作模式。
- 提供基础使用路径与高级自定义 Provider 路径；高级路径允许专家填 API/Gateway/自定义模型，但不能成为新手必须经过的步骤。云端涉及密钥/成本/隐私需明确同意，密钥不在普通前端/日志暴露。
- Whisper/FFmpeg/UVR/CUDA/Gradio 等属于实现细节：优先经 Core 的供应链管理器做依赖诊断，用户只需要看到“音频处理组件缺失 / 是否安装”。硬件与资源预估无证据则标未知，不编造 CPU/GPU 门槛。
- 安全规范不因易用性降低：Worker NEVER_WRITE、WeChatAgent 身份授权、SAVED!=APPLIED、UNKNOWN 不自动重发、用户必须明确批准真实微信发送和涉及系统改变的操作。

## 4. 开发任务书与最终验收强制门禁

每份 Plan 05/06/07/08/09/10/11/12/13/14 及后续扩展的 Level 2 任务书，应专设“**非程序员首次使用验收（Novice First DoD）**”，至少包括：

1. 用户没有技术背景、不会命令行，不需要手动编辑 JSON/ENV 或运行 Python 才能完成**已声明支持**的正常入门路径；目前尚未实现的能力须明确标未接入，不得虚假通过。
2. 空白首次进入 Voice 与 Singing 的默认流程；必需与可选组件清晰，云端/CPU/本地资源取舍有真实说明；“稍后再说”不死锁；不强制安装另一页组件。
3. 所有会产生下载/文件写入/驱动安装/收费/音频录制/微信消息的操作都清楚解释、主动确认；自动检测只能只读进行。
4. 一个普通用户在操作失败后能通过按钮和明确中文提示继续、切换合法方案或返回，并可自助找到组件状态；不得要求查看 DevTools/复制堆栈/执行 Shell 才可处理普通失败。
5. 执行 Fake/离线 UI 测试与真实机器分级测试：首次/再次进入、取消、无显卡、断网、无权限、空间不足、模型缺失、版本不兼容、Core 离线、重复共享依赖、窄屏与键盘访问。Fake 通过≠真实安装/发送完成。
6. 交付演示/验收报告必须包含“面向小白的操作步骤（从打开界面到得到结果）”“当前哪里仍需手动操作”“已知不可用环节与原因”“下一阶段怎样移除人工步骤”。一份只列 API/代码测试而没有用户流程证据的任务书或 PR，不能宣布完整产品 UX 验收通过。
